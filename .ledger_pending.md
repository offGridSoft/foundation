# Foundation Pending Ledger

Status: Draft inventory for review
Scope: Foundation itself; consumer migrations are deliberately excluded

## Operating rule

This ledger records unfinished contract work. A row moves to
`.ledger_completed.md` only when its package specification, clean-cut
implementation, hostile tests, macOS/Linux/Windows proof, and gates are
complete.

No pending item authorizes an alias, forwarding wrapper, compatibility package,
optional-field request soup, or fake test.

## Stable names

| Current | Intended | Decision |
| --- | --- | --- |
| `core` | `core` | Keep universal contracts; move time, currency, Garble, storage, and product facts to precise owners. |
| `core` time types | `temporal` | Clean move into the temporal domain. |
| `core` byte types | `core` | Keep as universal contracts required by multiple capability packages. |
| retired core money type | `currency.Amount` | Completed clean replacement with currency-bearing signed minor units; no alias survives. |
| `contextcheck` | `contextstate` | Rename cleanly. It validates context ingress and classifies terminal state. |
| `exchange` | `exchange` | Keep. Use intent verbs centered on transmit and receive. |
| `durability` | `durability` | Keep. The contract is durable state, not a raw file write. |
| scattered storage transfer | `objectstore` | Consolidate signed O(1) upload/download and integrity proof. |
| `hostresource` | `hostresource` | Keep. It observes host resources without owning policy. |
| `shutdown` | `shutdown` | Keep. “Graceful” describes quality; shutdown names the operation. |
| `keygen` | `keygen` | Keep. It is short, conventional, and does one thing. |
| Garble types in `core` and `release` | `garble` | Consolidate custody seed, derivation, version, and arguments. |
| none | `probe` | Add only after its safe request/result specification is approved. |
| `durabilitytest` | `durabilitytest` | Keep as test-only fault-injection support. |
| `testserial` | `testserial` | Keep as a compiler-visible testing declaration. |

Existing product protocol packages are migration sources, not approved
Foundation families. Product-owned contracts move to their owning modules.
Only product-neutral mechanics and values remain in Foundation.
